## 1. Problems in the app

Prompt Copilot:

```text
Hey copilot below are listed some issues that may or may not exist in this codebase;

- Multiple classes per file, rather than a class-per-file.
- Missing GlobalUsings.cs file which would reduce usings header bloat.
- Missing appsettings.json and appsettings.Development.json (should be standard in any new .NET project)
- Models/DTOs outside of the Models/ folder and not part of the [AppName].Models namespace.
- Services outside of the Services/ folder and not part of the [AppName].Services namespace.
- Missing OpenAPI/Swagger Web UI to allow us to test these endpoints via a browser
- Missing FeedbackApi.http file pre-configured to allow us to the vscode REST extension to test.

Do any of these issues exist?
```

## 7. Copilot Power-User Instructions

```text
Here are some additional instructions I would like to add to the copilot-instructions.md file;

- All public classes/properties/interfaces should have XML comments.
- Interface implementations should own the primary XML comments, any implementations of those interfaces shouldnt repeat the same XML comments they should use <inheritdoc/> instead.
- Interfaces are abstractions, so their naming should not be directly related to a class, e.g. 'FileService : IFileService' is pointless. The interface name should be abstract e.g. 'FileService : IDataStorage'
- When there is only a single known implementation of a c# interface, ask the user if they really need the interface and the complications/obsfucations that entail.
- C# class/record/interface names should map directly to their filenames, i.e. 'public class MyClass' == MyClass.cs'
- When being asked to rename a file and/or rename a c# class ensure to first stage perform a 'git mv' to preserve all git history and then proceed with any edits to the file.
- When multiple files are changed and you are asked to "commit all changes" attempt to split the edited files into batches and commit each batch with a respective message to account for the changes.
- When commiting do not include copilot attribution, e.g. "Authored by copilot" or "generated by copilot" - this is just noise!
- Web API Controllers should be "thin" with the majority of the logic held in external Services that are added to the DI container, the Controllers themselves should only hold Web API specific attributes.
```
